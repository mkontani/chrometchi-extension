# Chrometchi Rebuild — Plan 2: Art Production with PixelLab

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks that call PixelLab need a session where the `mcp__pixellab__*` tools are connected.

**Goal:** Produce every sprite, icon, effect, background and UI frame in the chosen style A, with owner approval at four gates, and drop them into the asset paths that Plan 1's registry already resolves.

**Architecture:** Generate with PixelLab `create_image_pixen` (1 generation per image). Derive poses from each approved base sprite with `edit_image_pixen` (1 generation per pose). Snap every character's frames together onto one master palette with `reduce_colors` (0.1 generation). Review candidates on contact sheets in the brainstorm visual companion. A small TypeScript tool validates size, transparency and palette before any file lands in `src/assets/`.

**Tech Stack:** PixelLab MCP, `pngjs` for validation, `tsx` to run scripts, the superpowers brainstorm visual companion for review.

**Spec:** `docs/superpowers/specs/2026-11-03-chrometchi-rebuild-design.md` (§3 art direction, §6 UI, §9 budget)

**Depends on:** Plan 1 Task 2 (`src/data/forms.ts` with ids and `motif`) and Task 13 (asset paths and `IconId`/`EffectId`/`BackgroundId`). Plan 2 Tasks 1–4 can run in parallel with Plan 1 Tasks 3–20.

## Global Constraints

- Style A (spec §3): 32×32 canvas, thick single-color black outline, flat colors with at most one shade step, low detail, bright colors, big eyes, rosy cheeks, front-facing full body, transparent background. References: `docs/superpowers/specs/assets/style-a-{baby,dragon}.png`.
- Every character design is original. Do not use prompts or results that resemble existing franchise characters or devices.
- Every finished PNG uses only colors from `src/assets/palette.json` (≤ 32 colors, plus full transparency). Alpha is either 0 or 255.
- Generation params for every character base sprite: `create_image_pixen(width 32, height 32, no_background true, outline 'single color black outline', detail 'low detail', direction 'south', view 'side')`.
- Budget (spec §9): about 1,500 generations per month as a guide. Call `get_balance` before every batch, and record the spend in the task's commit body. Never buy or use paid credits. If `generations_remaining` < 100, stop and ask the owner. Plan total ≈ 700.
- **Owner gates are blocking.** At gates A–D, push a contact sheet to the visual companion and stop until the owner approves in the terminal. The companion is started with `bash <superpowers>/skills/brainstorming/scripts/start-server.sh --project-dir <repo> --open`; `<superpowers>` is the brainstorming skill's plugin directory.
- Keep raw candidates in `art-work/` (gitignored). Only approved, validated files go to `src/assets/`.
- Asset paths (from Plan 1 Task 13):
  - Sprites: `src/assets/sprites/<formId>/<pose>.png`.
  - Icons: `src/assets/ui/icons/<IconId>.png`.
  - Effects: `src/assets/ui/effects/<EffectId>.png`.
  - Backgrounds: `src/assets/ui/bg/<BackgroundId>.png`.

## Review Focus

1. **A candidate that looks fine at 1× but breaks at 4×.** For example stray pixels, outline gaps, or a half-transparent fringe. Test: the Task 1 validator `partialAlpha` check. At each gate, review the contact sheet at 4×.
2. **Poses drifting from the base design.** For example a color change, a different silhouette, or extra limbs. Test: the Task 4 pose gate sheet puts all 7 poses of a character in one row. Re-run the edit if the base identity is lost.
3. **Palette snapping that crushes the eyes or cheeks.** For example white eye highlights merged into a light body color. Test: the Task 2 palette must keep `#ffffff`, a pink cheek, and the black outline as separate entries. The validator reports colors lost compared with the source.
4. **Two adults that look alike.** For example two round green blobs, which hurts the "many branches" goal. Test: the Gate B sheet groups forms by family. The owner checks that siblings are distinct, and Task 3 re-rolls look-alikes.
5. **A missing pose file silently falling back to `idle0`.** Test: the Task 7 completeness test lists every required path.

### Task 1: Art validation and contact-sheet tooling

**Files:** Create `scripts/art/{lib,check,sheet}.ts` and `scripts/art/lib.test.ts`. Modify `package.json` (dev deps `pngjs`, `@types/pngjs`, `tsx`; script `art:check`) and `.gitignore` (`art-work/`). Make sure `vitest.config.ts` includes `scripts/**/*.test.ts`.

**Interfaces — Produces:**

```ts
export type Issue = { file: string; kind: 'missing'|'size'|'opaqueBackground'|'partialAlpha'|'offPalette'|'tooManyColors'; detail: string }
export function readPng(file: string): { width: number; height: number; data: Uint8Array } | null
export function opaqueColors(png): string[]                      // unique '#rrggbb' of alpha-255 pixels
export function checkImage(file: string, opts: { width: number; height: number; palette?: string[]; maxColors?: number; transparentCorners?: boolean }): Issue[]
export function requiredSpritePaths(forms: readonly FormDef[]): string[]   // egg: idle0,idle1; others: all 7 poses
```

`check.ts` usage: `npx tsx scripts/art/check.ts [--size 32x32] [--palette] [--opaque] <files...>`. The default size is 32×32. `--palette` checks against `src/assets/palette.json`. `--opaque` skips the transparent-corner check (for backgrounds). It prints one line per issue and exits 1 if there are any.

`sheet.ts` usage: `npx tsx scripts/art/sheet.ts --title "<question>" --out <companion content dir>/<name>.html --group "<label>" <files...> [--group ...]`. It copies the files into the content dir and writes a `cards` fragment. Each image is shown at 4× with `image-rendering: pixelated` and gets `data-choice="<relative path>"` plus `onclick="toggleSelect(this)"` (multi-select).
