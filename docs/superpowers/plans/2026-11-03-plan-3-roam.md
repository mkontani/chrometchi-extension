# Plan 3: Browser roaming (おさんぽ) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the owner turns it on, the pet walks along the bottom of the web pages they browse; clicking it shows a short status line, it can be dragged aside or hidden per site, and nothing is asked for at install time.

**Architecture:**
- **Content script.** A WXT content script registered at runtime, never in the manifest, draws the pet with vanilla DOM in an open Shadow DOM.
- **State.** It reads the save straight from `chrome.storage.local` and re-renders on `storage.onChanged`, so the background stays the only writer.
- **Sprites.** It asks the background for the current pet's frames as data URLs.
- **Background.** It owns the host permission and the script registration, and keeps both in step with `settings.roam`.
- **Pure rules.** Motion, bubble text and site rules are pure functions, so they can be tested in isolation.

**Tech Stack:** WXT 0.21 (`registration: 'runtime'` content script), TypeScript, Zod 4, `chrome.scripting` / `chrome.permissions`, Vitest + happy-dom, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-chrometchi-rebuild-design.md`, section 7 (ブラウザ徘徊), plus sections 8 and 9 for permissions.

## Global Constraints

- **Permissions at install and update:** no host permission and no warning (spec 8 and 9).
  - The only manifest permission added is `scripting`, which shows no warning.
  - Host access is `optional_host_permissions` only, requested when roaming is turned on and removed when it is turned off.
- `ROAM_ORIGINS = ['http://*/*', 'https://*/*']` is used everywhere: optional host permissions, script matches and tab queries.
  - Ruling: http and https only, instead of the spec's `<all_urls>` example. This leaves `file://` pages alone and asks for the same access.
- **The content script must not end up in the manifest.** It uses `registration: 'runtime'` with `matches: []`. WXT copies a runtime script's `matches` into `host_permissions`, so they must stay empty. `src/manifest.test.ts` pins the result.
- **Roaming must not get in the page's way** (spec 7):
  - The host covers no page area that takes input. Only the pet and its bubble receive pointer events.
  - The pet is drawn at 64px (32px art at 2×, `image-rendering: pixelated`).
  - Its `z-index` is `2147483647`.
  - It only runs in the top frame.
- Messages from content scripts can do exactly two things: hide the current site, and fetch the current pet's sprite frames. Every other request from a web-page sender is refused.
- **Sprite delivery: no `web_accessible_resources`, and nothing inlined into the content script.**
  - Exposing extension files to every site would let pages detect the extension.
  - Inlining all frames would add about 600KB to every page.
  - Instead, Vite emits sprites as files (`assetsInlineLimit` returns `false` for `/src/assets/sprites/`).
  - The background fetches only the current pet's frames and returns them as data URLs (Task 6).
- All new UI text goes into both `public/_locales/en` and `public/_locales/ja`.
- Project rules:
  - TDD.
  - Coverage of 80% or more.
  - Functions under 50 lines, files under 800 lines.
  - Immutable updates.
  - No `console.log`.
  - Conventional commits with no attribution trailer.
- Art: the only new sprites are Task 1's walk loops. They follow `docs/art/style-guide.md`, need the owner's gate, and generation stops if `generations_remaining` < 100.

## Review Focus

1. **A save from before this plan, with no `roam` or `roamHiddenSites`.** It must load with roaming off and the pet and zukan intact, not reset. Test: Task 2.
2. **An `updateSettings` patch that leaves out the roam fields**, for example `{ sound: true }`. It must not reset them. Zod 4 defaults inside `.partial()` would silently fill them in. Test: Task 2.
3. **Host access revoked outside the popup** (on `chrome://extensions`). Roaming must turn off and the script must be unregistered. Turning roaming off must also drop the permission. Test: Task 4.
4. **Pages that load the script twice** (open tabs injected when roaming turns on, then a re-navigation), and **pages with `prefers-reduced-motion`.** Both must show one pet, and the reduced-motion one must stand still. Test: Task 7.
5. **A background tab or a resized window.**
   - When a background tab wakes after minutes asleep, the pet must not jump or tunnel out of view.
   - When the window shrinks, the pet must stay on screen.
   - Test: Task 5 (`stepWalker` clamps `dt` and `x`).

### Task 4: Permission, script registration and manifest

**Files:**
- Create: `src/roam/constants.ts`, `src/background/roam.ts`, `src/background/roam.test.ts`
- Modify: `wxt.config.ts`, `src/manifest.test.ts`, `src/entrypoints/background.ts`, `e2e/global-setup.ts`

**Interfaces:**
- Produces:
  - `src/roam/constants.ts`:
    - `ROAM_ORIGINS = ['http://*/*', 'https://*/*'] as const`
    - `ROAM_SCRIPT_ID = 'chrometchi-roam'`
    - `ROAM_SCRIPT_FILE = 'content-scripts/roam.js'`
  - `createRoamManager(deps: RoamDeps): { sync(settings: Settings): Promise<void> }` in `src/background/roam.ts`.
    - `RoamDeps` holds the narrow slices of `scripting`, `permissions` and `tabs` it uses, plus `reportError(err, context)`.
  - `sync` is idempotent, and its steps run in this order:
    1. `want = settings.roam && await permissions.contains({ origins: [...ROAM_ORIGINS] })`.
    2. `have` = whether `getRegisteredContentScripts({ ids: [ROAM_SCRIPT_ID] })` returns anything.
    3. If `want && !have`:
       - call `registerContentScripts([{ id, matches: [...ROAM_ORIGINS], js: [ROAM_SCRIPT_FILE], runAt: 'document_idle', persistAcrossSessions: true }])`;
       - then, for every tab from `tabs.query({ url: [...ROAM_ORIGINS] })`, call `executeScript({ target: { tabId }, files: [ROAM_SCRIPT_FILE] })`. A failure on one tab is reported and skipped; the rest still run.
    4. If `!want && have`: `unregisterContentScripts({ ids: [ROAM_SCRIPT_ID] })`.
    5. If `!settings.roam`: `permissions.remove({ origins })`. Errors are reported, never thrown, because the e2e build declares the origins and they cannot be removed.
  - Manifest (`wxt.config.ts`), with `manifest` becoming a function of `{ mode }`:
    - `permissions`: `['storage', 'alarms', 'notifications', 'idle', 'scripting']`
    - `optional_host_permissions`: `[...ROAM_ORIGINS]`
    - In `mode === 'e2e'` only, also `host_permissions: [...ROAM_ORIGINS]`, so Playwright never has to answer Chrome's permission dialog.
  - `vite.build.assetsInlineLimit = (file) => (file.includes('/src/assets/sprites/') ? false : undefined)`, so sprites are emitted as files. The popup keeps working, because extension pages resolve `/assets/...` against the extension.
  - `e2e/global-setup.ts` builds with `npx wxt build --mode e2e`. `scripts/screenshots.ts` keeps `npm run build`, the production build.
  - Background wiring:
    - On worker start, load the save and call `roam.sync(save.settings)`.
    - The listener's `onHandled` calls `roam.sync(res.save.settings)` when `res.ok`.
    - `permissions.onAdded` with both `ROAM_ORIGINS` → `engine.handle({ type: 'updateSettings', patch: { roam: true } })`. This covers a popup that closed while Chrome showed the dialog.
    - `permissions.onRemoved` with either origin → the same with `roam: false`.
    - Both handlers then call `sync`.

### Task 5: Roaming rules (pure)

**Files:**

- Modify: `src/roam/constants.ts`

**Interfaces:**
- Produces:
  - Constants:
    - `PET_PX = 64`
    - `WALK_PX_PER_S = 40`
    - `WALK_MS = [3000, 8000]`
    - `REST_MS = [1500, 5000]`
    - `FRAME_MS = { walk: 110, rest: 500 }`
    - `MAX_DT_MS = 100`
  - `src/roam/walker.ts`:
    - `interface Walker { x: number; dir: 1 | -1; mode: 'walk' | 'rest'; modeLeftMs: number; clockMs: number }`
    - `frameIndex(w: Walker, count: number): number` = `Math.floor(w.clockMs / FRAME_MS[w.mode]) % count`. `clockMs` restarts at 0 on every mode switch.
    - `createWalker(width: number, rng: Rng): Walker` starts at a random `x` within `[0, width - PET_PX]`, resting.
    - `stepWalker(w: Walker, dtMs: number, width: number, rng: Rng): Walker`:
      - clamp `dt` to `MAX_DT_MS`;
      - when walking, move `dir × speed × dt` and turn around at either edge;
      - when the mode's time runs out, switch between walk and rest, with a new duration drawn from that mode's range and, when switching to walk, a random `dir`;
      - advance `clockMs` by `dt`;
      - always clamp `x` into `[0, max(0, width - PET_PX)]`.
    - `dragWalker(w: Walker, x: number, width: number): Walker` sets a clamped `x` and switches to rest for `REST_MS[0]`.
  - `bubbleKey(pet: PetState): string` in `src/roam/bubble.ts` returns the first of these that applies:
    1. egg → `'roam_say_egg'`
    2. asleep → `'roam_say_sleep'`
    3. `deriveWarning(pet) === 'critical'` → `'roam_say_critical'`
    4. `'danger'` → `'roam_say_weak'`
    5. sick → `'roam_say_sick'`
    6. `poops > 0` → `'roam_say_poop'`
    7. `hunger < 25` → `'roam_say_hungry'`
    8. `mood < 25` → `'roam_say_bored'`
    9. otherwise → `'roam_say_happy'`
  - `src/roam/display.ts`:
    - `type RoamDisplay = { kind: 'hidden' } | { kind: 'pet'; pet: PetState; generation: number; motion: 'walk' | 'still'; pose: 'idle' | 'sleep' }`
    - `roamDisplay(save: SaveV1 | null, host: string | null, reducedMotion: boolean): RoamDisplay` returns:
      - `hidden` when `save` is null, `!settings.roam`, `lifecycle !== 'alive'`, `host` is null, or the host is hidden;
      - otherwise a pet:
        - egg → `still` + `idle`;
        - asleep → `still` + `sleep`;
        - `reducedMotion` → `still` + `idle`;
        - else → `walk` + `idle`.

### Task 7: The roaming content script

**Files:**
- Create: `src/roam/view.ts`, `src/roam/styles.ts`, `src/roam/view.test.ts`, `src/entrypoints/roam.content.ts`
- Modify: `public/_locales/{en,ja}/messages.json`, `vitest.config.ts` (only if the entry needs excluding, as other entrypoints are)

**Interfaces:**
- Consumes: Tasks 3, 5 and 6.
- Produces:
  - Frames come from Task 6. The content script sends `{ type: 'roamFrames' }` on mount and again whenever `` `${formId}:${generation}` `` changes in storage. Until frames arrive it renders nothing.
  - `src/roam/view.ts`:
    - `mountRoam(doc: Document, deps: RoamViewDeps): RoamView`; `render(display, frames: RoamFrames | null)`. Where:
      - `RoamViewDeps = { t: (key: string) => string; onHide(): void; rng: Rng }`;
      - `RoamView = { render(display: RoamDisplay): void; destroy(): void }`.
    - It creates one `<chrometchi-roam>` element on `doc.documentElement` with an **open** shadow root. If one already exists, it removes it before creating its own, so a re-run never leaves two pets.
    - Host style: `position: fixed; left: 0; right: 0; bottom: 0; height: 0; z-index: 2147483647; pointer-events: none`.
    - The pet is a `<button class="pet">` holding an `<img>` with `pointer-events: auto`. Its `aria-label` is `t('form_<formId>')`.
    - A `requestAnimationFrame` loop drives `stepWalker` with `innerWidth`.
      - It sets `transform: translateX(x) scaleX(walking ? dir : 1)`, so only the side-facing walk is mirrored.
      - It shows `frames.walk[frameIndex(w, frames.walk.length)]` while walking and `frames.rest[...]` while resting.
      - In `still` it shows `frames.rest` (the egg wobble) or `frames.sleep`, and does not move.
    - Pointer handling:
      - `pointerdown`, then a `pointermove` of more than 4px, starts a drag that calls `dragWalker`;
