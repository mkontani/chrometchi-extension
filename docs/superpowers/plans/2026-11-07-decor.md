# Furniture Implementation Plan (stage 3 of 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The player buys furniture with coins in a new かぐ tab in おみせ. The もようがえ screen gets a かぐ tab where the furniture goes into each room's fixed slots. The stage draws the placed furniture by day and by night.

**Architecture:**
- **Data.** `src/data/decor.ts` lists the 28 items: the slot kind each fits, its 「種類」 and its price. `src/data/slots.ts` holds each room's slot rectangles in stage px. Indoor rooms have six slots; outdoor rooms have floor L, floor R and the rug.
- **Rules.** `src/core/decor.ts` holds `buyDecor` and `placeDecor`. They are pure and return an outcome, like `sellFood`. `placeDecor` reuses stage 2's `roomRefusal`.
- **Save.** `home` gains `ownedDecor` and `decor`, a per-room map from slot to item. Stage 2's `parseHome` already passes unknown fields through. This plan gives those two fields a real never-failing parser.
- **Popup.**
  - おみせ and もようがえ both get tabs. The もようがえ tabs sit in the overlay's header row, to keep the room list's height.
  - The stage draws the placed items between the room picture and the pet, in layers.

**Tech Stack:** Preact, TypeScript, Zod 4, Vitest + @testing-library/preact (happy-dom), Playwright e2e, pngjs art scripts.

**Spec:** `docs/superpowers/specs/2026-11-07-home-shop-and-new-forms-design.md`. This plan covers:
- chapter 3 (stage 3), chapter 7 except 7.3's evolution use;
- the かぐ parts of 11.2 and 11.3;
- the stage-3 parts of 12 and 13;
- appendix B, and the slot values in appendix D.

**Builds on stages 1–2, merged to main:**
- `progress.coins`, `addCoins`, `REWARD_IDS`
- `home.room`, `ownedRooms`, `shownRoom`, `roomRefusal(pet, claimed, room)`
- `ROOM_IDS`, `ROOMS[].outdoor`
- `PetStage` with `room`
- `DecorateOverlay` and `RoomPicker`, `ShopView` and `CoinAmount`
- `isHomeOutcome`, which keeps overlay outcomes off the home screen
- `useScrollCue` and `MoreCue`
- The slot exceptions written in `docs/art/style-guide.md` → "Slot exceptions for stage 3".

**Owner decisions for this stage:**
- No starter furniture. Every item is bought.
- Furniture is drawn at 2× (owner approved the mock-up on 2026-11-07).
- Slots are fixed, not free placement.

**Not in this plan:**
- Furniture as an evolution input. That is stage 5, which reads the 「種類」 defined here.
- Accessories (stage 4).
- The 20–30 generation balance test. It needs accessory prices too, so it moves to stage 4. This is a ruling, recorded in the ledger.

  - Kind ids in code: `light | water | plant | sky | gadget | night | sparkle | cozy`.
- **Slots.**
  - Ids: `wallL wallR ceiling rug floorL floorR`.
  - Kinds: wall (wallL, wallR), ceiling, rug, floor (floorL, floorR).
  - Indoor rooms have all six slots. Outdoor rooms (garden, beach, forest, snowfield) have only `floorL`, `floorR` and `rug`.
  - Starting rectangles, in stage px (x, y, w×h), from spec appendix D:

    | slot | rect |
    |---|---|
    | wallL | (24, 24, 56×56) |
    | wallR | (272, 24, 56×56) |
    | ceiling | (112, 0, 128×40) |
    | floorL | (12, 156, 72×76) |
    | floorR | (268, 156, 72×76) |
    | rug | (128, 204, 96×48) |

  - Task 3 tunes them per room around the slot exceptions.
  - Floor slots never overlap the pet's box (stage x 112–240, y 100–228).
- **Placement.**
  - One item per slot. Placing into a filled slot replaces the item there.
  - An owned item may be placed in any number of rooms, but only once per room. Placing it into another slot of the same room moves it.
  - `null` clears a slot.
  - The decor of each room is remembered when the room is switched.
- **Drawing (spec 7.2).**
  - Items are drawn at 2×: 32 px art at 64 px, 24 px art at 48 px.
  - Alignment:
    - floor: bottom-centred in the slot;
    - wall and rug: centred;
    - ceiling: top-centred.
  - Layer order, back to front: room picture → wall and ceiling → rug → pet → floor.
  - While the pet is asleep (the night picture), the items are darkened too. Use a CSS filter close to the night pictures' tone.
  - The lights-off darkness overlay still covers everything.
- **Buying.**
  - おみせ is open at any time.
  - You can't buy an item twice (`owned`) or without enough coins (`noCoins`).
  - Coins never go below 0.
  - A confirm dialog (`ConfirmDialog`) asks 「◯◯を △コインで かう？」 before each buy.
- **Placing.**
  - Refusal order: `roomRefusal(pet, claimed, room)`, which covers notAlive, egg, asleep and locked. Then `noSlot` (the room has no such slot), then `notOwned`, then `wrongSlot` (the item's slot kind differs).
  - もようがえ stays disabled while the pet is asleep or an egg, as in stage 2.
- **Save format.**
  - Keep `version: 1`.
  - `home.ownedDecor`:
    - drop unknown ids;
    - drop repeats, keeping the first.
  - `home.decor`:
    - drop unknown rooms;
    - drop slots that room does not have;
    - drop unknown items, items not owned, and items whose slot kind does not fit;
    - when the same item appears twice in one room, keep the first slot in `wallL, wallR, ceiling, rug, floorL, floorR` order.
  - Parsing never fails the save (stage 1's ruling P1).
  - Unknown top-level `home` fields still pass through, for stage 4.
- **Repo rules.**
  - TDD: watch each test fail first.
  - Coverage stays about where it is.
  - Functions < 50 lines, files < 800 lines.
  - Immutable updates. No `console.log`.
  - UI text goes in both locales. Message JSON diffs only add lines, with Japanese left unescaped.
  - Accessible names on new controls.
  - Do not run prettier.
- **Commits.** Conventional format, **no attribution trailer**. Never push, open a PR or merge without the owner's say-so.
- **Language.** Talk to the owner in Japanese. Code, comments and test names stay in English.

## Review Focus

1. **Switching rooms after decorating.** Decorate the beach, switch to home, then back.
   - Expected: the beach's items are where they were, and home shows its own.
   - Tested in Task 2 (`decor is kept per room across room switches`).
2. **A stale or forged place request.** The item is not owned, the slot kind is wrong, an outdoor room has no wall, the room is locked, or the pet is asleep.
   - Expected: the request is refused with the right reason, and `home` is unchanged.
   - Tested in Task 1 (`placeDecor refusals in order`) and Task 2 (`placeDecor requests that are not known ids are rejected`).
3. **Buying with exactly enough coins, or one coin short. Buying twice from two popups.**
   - Expected: exact coins succeed and leave 0. One short is refused with `noCoins`. The second buy is refused with `owned`, and coins are taken once.
   - Tested in Task 1 (`buyDecor at exactly the price, one short, and twice`).
4. **The same item moved within a room.** The plant goes from floor L to floor R.
   - Expected: it leaves floor L. A room never shows the same item twice.
   - Tested in Task 1 (`placing an item already in the room moves it`).
5. **Night and lights-off with items placed.**
   - Expected: items darken with the night picture, and the lights-off overlay covers them too. No item stays bright in a dark room.
   - Tested in Task 4 (`placed items are dimmed while the pet sleeps`), and checked by eye at Gate N.
