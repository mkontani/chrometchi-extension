# お世話の演出 設計書

- 日付: 2026-11-03
- 対象: `chrometchi-extension` のポップアップ(1.0.0 の上に追加)
- 状態: オーナー確認待ち

> 表記ルール: **【オーナー】** はオーナーが会話で決めたこと(提案への「OK」も含む)。**【判断】** は設計者(Claude)が任された範囲で決めたことで、ビルダーが理由を持って変えてよい。

---

## 1. 何を、なぜ作るか

- 【オーナー】1.0.0 で少し遊んでみたが、エフェクトがなさすぎて物足りない。
- 今の様子:
  - ごはん: 「食べる」ポーズを1秒見せるだけ。
  - そうじ: ボタンを押した瞬間に、うんちが消える。
  - おくすり: 何も起きない。
  - でんき: 部屋が一瞬で暗くなる(明るくなる)だけ。
  - 【オーナー】おくすりとでんきは、何も起きなくて寂しい。

お世話をしたときに、**何をしてあげたのかが目で見て分かり、手応えがある**ようにする。1回に遊ぶのは1〜3分(本体の設計書 1章)なので、演出は短く、遊びのテンポを崩さない。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
4つのお世話(ごはん・そうじ・おくすり・でんき)を実行したとき、ステージ上で短い演出が流れる。

### 非ゴール(今回やらない)
- おさんぽ中のペット(Web ページ上)の演出。
- 「あそぶ」と「なでる」の演出の変更。今のうれしいポーズ、キラキラ、音符のままにする。
- 孵化・進化・死亡の演出。将来の候補にする。
- 断られたお世話(おなかいっぱい、うんちがない、など)の演出。今のトーストのままにする。

### アンチゴール(技術的に動いても失敗とみなすもの)
- 演出が長くて、次のお世話を待たされる(どれも3秒以内)。
- なめらかすぎる動き。ドット絵の世界観から浮く(動きは表示上のドット単位で、カクカク動かす)。
- 演出のせいで状態の見え方がおかしくなる。
  - 例: 掃いたうんちが一瞬戻る。
  - 例: 治ったのに汗が残る。
- 絵が安っぽい、または既存の絵と絵柄がそろっていない。

## 3. 演出の中身

各演出の時間はすべて目安【判断】で、ビルダーが見た目で調整してよい。

### 3.1 ごはん(約2.5秒)
- 【オーナー】食べ物が出てきて、パクパク食べて、減っていく。
- 選んだ食べ物(ごはんパネルと同じ絵)が、ペットの口元に出てくる。おやつ(ケーキ・あめなど)も同じ流れ【判断】。
- ペットが「食べる」ポーズ(口を開ける)と「ふだん」のポーズ(`idle0`、口を閉じる)を交互に繰り返し、パクパク食べる【判断】。
- ひと口ごとに、食べ物が欠けていく【判断】。
  - 3口で 丸ごと → 2/3 → 1/3 → なくなる。
  - ひと口ごとに、食べかすが少し飛ぶ。
- 食べ終わったら、満足そうな「うれしい」ポーズを一瞬見せる【判断】。
- 今の「食べるポーズを1秒」の反応は、この演出に置き換える。

### 3.2 そうじ(約2秒)
- 【オーナー】ほうきが出てきて、うんちを掃いて、うんちが消える。
- ほうきが横から入り、床のうんちの上を左右に往復する【判断】。
- ほうきが通ったうんちは、少し滑ってから、ほこりの煙を出して消える【判断】。
- うんちは、ほうきが届くまで画面に残す【判断】。
  - お世話はボタンを押した時点で保存されているので、画面には掃除する前の数を表示する。
- 全部消えたら、ほうきは画面の外へ出ていく。そのあと、きれいになった床がキラッと光り、ペットが「うれしい」ポーズを一瞬見せる【判断】。
- うんちの数が違っても、演出の長さは変えない【判断】。

### 3.3 おくすり(約2秒)
【オーナー】(設計者の提案に「OK」)

病気は、おくすりを2回飲むと治る(`MEDICINE_DOSES = 2`)。

- 錠剤(今ある `pill` の絵)がふわっと現れて、ペットの口に入る。ペットは「食べる」ポーズでゴクンと飲みこむ。
- 1回目(まだ治らない):
  - ペットが病気のポーズのままブルッと震え、汗も残る。
  - 「あと1回」と分かるように、小さなキラキラを控えめに出す(数を少なく、または半分の大きさで)。
- 2回目(治った):
  - 汗が飛んでいき、キラキラがパッと広がる。
  - ペットは病気のポーズから「うれしい」ポーズに変わる。

### 3.4 でんき(約1秒)
【オーナー】(設計者の提案に「OK」)

でんきを消せるのは、ペットが寝ているときだけ。卵も消せる。

- 消す:
  - スイッチ(でんきボタンと同じ絵)が「カチッ」と押され、部屋が端からすうっと暗くなる。
  - 暗くなった部屋で、寝ているペットの上に小さな星がまたたく。
  - 星は、部屋が暗いあいだ出し続ける【判断】。
    - 星は「暗い部屋のふだんの見た目」として扱う。でんきを消した直後だけでなく、暗い部屋でポップアップを開いたときも出す。
    - 表示は保存された状態(寝ている・でんきが消えている)から決める。演出が受け持つのは、明るい部屋から暗い部屋へ切り替わる約1秒だけ。
    - 「視差効果を減らす」がオンのときは、星をまたたかせずに止めて出す。
- つける:
  - 部屋がパッと明るくなる。
  - 寝ているペット(卵を含む)が「まぶしい」とモゾッと動く。体を左右に小さく揺らす【判断】。

## 4. 共通のふるまい【判断】

- **お世話の結果は、今までどおりボタンを押した時点で決まり、保存される。** 演出は見た目だけ。演出の途中でポップアップを閉じても、何も失われない。
- 演出のあいだもボタンは押せる。別のお世話が成功したら、今の演出をやめて、新しい演出に切り替える。断られたお世話は演出を止めず、トーストだけ出す。
- 演出が終わったら、ステージは今の状態(保存された状態)の表示に戻る。
  - 演出の途中に状態が変わることがある(新しいうんちが出る、寝る、など)。その場合も、終わった時点の状態を表示する。
- OS の「視差効果を減らす」設定(`prefers-reduced-motion`)がオンのとき:
  - 動きと点滅を省いた短い版(1秒以内)にする。
  - 例: 食べ物の絵と「食べる」ポーズを見せて、終わる。
  - でんきは、ふわっと切り替えずにすぐ切り替える。
- 効果音(設定でオンのときだけ)は、今のチップチューンの仕組みで鳴らす。ひと口・掃く・ゴクン・カチッ に短い音を合わせる。新しい音は今の音と同じ雰囲気の短いものにする。
- 動きはドット絵らしく、表示上のドット単位で段階的に動かす(CSS の `steps()` など)。絵は整数倍で拡大する。

## 5. 絵【判断】

- 使い回すもの(新しく描かない):
  - 食べ物6種類の絵
  - 錠剤(`pill`)、キラキラ(`sparkle`)、汗(`sweat`)
  - でんきボタンの絵(スイッチ)
  - ペットの各ポーズ(`idle0`・`eat`・`happy`・`sick`・`sleep`)
- 欠けた食べ物(2/3、1/3)は、今の食べ物の絵からスクリプトで作る。
  - 丸い「かじり跡」で切り抜き、切り口にも1px の黒い輪郭線を引き直す(スタイルガイドの「シルエット全体を1px の黒線で囲む」を守る)。
  - `scripts/art/` に、`idle1.ts` と同じように置く。
  - 食べ物が増えても、スクリプトを流すだけで対応できるようにする。
- ほうき:
  - まず、そうじボタンのほうき(16×16)を拡大して使う。
  - 確認会(6章)で物足りなければ、PixelLab で 32×32 のほうきを作る。
- 新しく作る小さな絵:
  - 食べかす、ほこりの煙(2〜3コマ)、星。
  - PixelLab、またはコードで描く。どちらでも、マスターパレットに合わせ、`scripts/art/check.ts --palette` を通す。
- PixelLab は、無料の月間枠の範囲だけで使う。`generations_remaining` が100未満なら、止めてオーナーに聞く(本体と同じルール)。
- 新しい絵とスクリプトの使い方は、`docs/art/style-guide.md` に追記する。

## 6. 確認の進め方【判断】

- 4つの演出が動いたら、マージする前に、オーナーに実際に動く様子を見せて承認をもらう(確認会)。見せ方は、録画した GIF か、動く確認用ページ。
- 見てもらうもの:
  - ごはん: 食べ物2種類
  - そうじ: うんち1個と3個
  - おくすり: 1回目と2回目
  - でんき: 消す・つける

## 7. 制約

- 本体の設計書(`docs/superpowers/specs/2026-11-03-chrometchi-rebuild-design.md`)の制約(9章)と開発ルールに従う:
  - TDD、カバレッジ80%以上
  - 関数は50行未満
  - 不変の書き方
  - 既存作品の模倣をしない
- 演出の進み方(何秒目に何を表示するか)は、時間を引数に取る純粋な関数として書き、単体テストで確かめる。ポップアップ全体の e2e テストにも、少なくとも1つの演出(ごはん)を足す。
- ゲームのルール(`src/core`)とセーブの形式は変えない。演出に必要な情報は、すべて UI 側で用意する。
  - ごはん: 選んだ食べ物の種類。
  - そうじ: 掃除する前のうんちの数。
  - おくすり: 治ったかどうか(お世話の後に病気が残っているか)。

## 8. ビルダーに任せること

- 演出の細かいタイミング、位置、コマ数。
- 演出の状態を持つ場所と、その仕組み(今の `useReaction` を広げるか、作り直すか)。
- 欠けた食べ物の絵を作るときのかじり跡の形と、新しい小さな絵の作り方(PixelLab か、コードか)。
- 効果音の音程と長さ。
