# 食材集めと料理 設計書

- 日付: 2026-11-04
- 対象: `chrometchi-extension` のポップアップとゲームのルール(1.0.0 + お世話の演出 の上に追加)
- 状態: オーナー承認済み(2026-11-04)

> 表記ルール: **【オーナー】** はオーナーが会話で決めたこと(提案への「OK」も含む)。**【判断】** は設計者(Claude)が任された範囲で決めたことで、ビルダーが理由を持って変えてよい。

---

## 1. 何を、なぜ作るか

- 今は「ごはん」パネルから、6種類の食べ物(ごはん・肉・魚・野菜・ケーキ・あめ)をいつでも出せる。手に入れる手間がないので、お世話が「ボタンを押すだけ」になっている。
- 【オーナー】ごはんの魚や肉は、ペット(たまごっち)が自分で調達するようにしたい。
  - 魚は釣り、肉は狩り、木の実は採集、野菜や果物は畑で手に入れる。
- 【オーナー】調達した食材を料理して、新しいごはんを作れるようにしたい。
  - 例: 肉2・野菜1でステーキ、魚2・野菜2でアクアパッツァ、果物3でケーキ。
  - 作れる料理は一覧から選ぶのではなく、**食材を自由に組み合わせて試しながら見つけていく**。

食材を集める → ためる → 組み合わせて料理を見つける → 食べさせる、という流れで、毎日ポップアップを開く楽しみを増やす。1回に遊ぶのは1〜3分(本体の設計書 1章)なので、どの遊びも短く手軽にする。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
- 4つの「おでかけ」(釣り・狩り・採集・畑)で食材が手に入る。
- 手に入れた食材を、そのまま食べさせることも、料理することもできる。
- 料理のレシピを自分で見つけ、見つけたレシピが残る。

### 非ゴール(今回やらない)
- おさんぽ中のペット(Web ページ上)が食材を集めること。
- 食材が時間で傷む・腐ること。
- 畑が収穫できるようになったときの通知やバッジ【判断】。今ある通知の種類は増やさない。
- お店や、お金のような通貨。
- 「あそぶ」の3つのミニゲーム(キャッチ・カップ・ストップ)の変更。今のまま残す【オーナー】。

### アンチゴール(技術的に動いても失敗とみなすもの)
- 【オーナー】**食材が全然取れない。** どんなに失敗しても、1回のおでかけで最低1つは手に入る。
- ペットが飢える。お米はいつでも出せるので、運や腕前のせいでペットが弱ることはない。
- 1回のおでかけが長くて、遊びのテンポを崩す(どれも約15秒)。
- 狩りが怖い・痛そうに見える。かわいい雰囲気のまま「つかまえる」見せ方にし、血やけがは描かない【判断】。
- 絵が安っぽい、または既存の絵と絵柄がそろっていない。
- 進化の分岐が、実際には選べなくなる(7.1)。

## 3. 食材と、いつでもあるもの

| 食材 | 入手 | 進化で数える種類【判断】 |
|---|---|---|
| お米 | **いつでもある**(数は減らない)【オーナー】 | grain |
| あめ | **いつでもある**【オーナー】。おやつ専用で、料理の材料にはしない【判断】 | sweet |
| 魚 | 釣り【オーナー】 | fish |
| えび(珍しい) | 釣り、たまに【オーナー】 | fish |
| 肉 | 狩り【オーナー】 | meat |
| たまご(珍しい) | 狩り、たまに【オーナー】 | meat |
| 木の実 | 採集【オーナー】 | grain |
| きのこ(珍しい) | 採集、たまに【オーナー】 | veggie |
| 野菜 | 畑【オーナー】 | veggie |
| 果物 | 畑【オーナー】 | sweet |

- 【オーナー】いつでも出せるのは、お米とあめだけ。今いつでも出せる肉・魚・野菜・ケーキは、手に入れたり作ったりしたものだけになる。
- 【オーナー】手に入れた食材は、料理しないでそのまま食べさせられる。
- 手に入れた食材と作った料理は「食料庫」にたまる【オーナー】。
  - 1種類あたり最大99個【判断】。それ以上は増えない。
- 食料庫とレシピ帳は、ペットが代わっても(死亡・やり直し・旅立ち)そのまま残す【判断】。ずかんと同じく「あなたの持ち物」として扱う。

## 4. おでかけ(食材集め)

### 4.1 共通のルール
- 【オーナー】新しいボタン「おでかけ」から、4つの活動を選ぶ。
- 【オーナー】簡単な操作のゲームにする。結果に応じて、手に入る食材の量や種類が変わる。
  - どんなに失敗しても、最低1つは手に入る。
  - 上手なほど数が増え、珍しい食材(えび・たまご・きのこ)が出やすくなる。
  - 1回で手に入るのは、目安として1〜4個【判断】。
- 【オーナー】(提案に「OK」)回数の上限: 釣り・狩り・採集は、それぞれ1日3回まで。
  - 「1日」はパソコンの日付で数え、日付が変わったら元に戻る【判断】。
  - 畑は、育つのを待つこと自体が制限になる。
  - 【判断】回数は、ゲームを最後まで遊んで結果が届いたときに1回と数える。途中でポップアップを閉じたら、回数も食材も変わらない。
  - 【判断】7.1 の条件を満たすための調整は、まず1回の収穫量で行う。上限の「1日3回」はオーナーが決めた数なので、変える必要が出たら、変える前にオーナーに聞く。
- 【オーナー】(提案に「OK」)卵のときと寝ているときは、おでかけできない。「ごはん」「あそぶ」と同じ扱い。病気のときはできる【判断】。
- 【オーナー】(提案に「OK」)おでかけしても、ペットのおなかやごきげんは変わらない。目的は食材を集めることだけ。
- 【判断】おでかけは「あそぶ」の回数(`gameCounts`)に数えない。大人への進化の分岐(どのミニゲームを多く遊んだか)は今のまま。
- 画面にはペットが出てきて、ペットが釣りや狩りをしている様子にする。プレイヤーはタップ(またはキー)で手伝う。

### 4.2 4つの遊び方 【オーナー】(提案に「OK」)
1回は約15秒。

- **釣り:** ウキがピクッと沈んだ瞬間にタップすると、魚が釣れる。早すぎると逃げられる。たまに、えびが釣れる。
- **狩り:** 草むらから飛び出したものを、すばやくタップしてつかまえる。肉が手に入り、たまに、たまごも見つかる。
- **採集:** 9つの茂みから、決まった回数だけめくって木の実を探す。たまに、きのこが見つかる。
  - 【判断】運だけにならないように、木の実がある茂みは少し揺れているなど、よく見ると分かる手がかりを入れる。
- **畑:** ほかの3つとちがい、反射神経のゲームではない。
  - 種(野菜か果物)をまくと、数時間で育つ。
  - 途中でポップアップを開いて水をやると、収穫が増える。
  - 育ったら収穫する。
  - 【判断】畑は1区画。種は無料で何度でもまける。
  - 【判断】育つ時間は、ペットと同じゲームの時間で進む(Chrome を閉じている間は進まない。本体の設計書のとおり)。

## 5. 料理とレシピ

### 5.1 料理のしかた 【オーナー】(提案に「OK」)
- 「ごはん」パネルの中に「りょうりする」タブを置く。ボタンは増やさない。
- 食材をタップすると鍋に入る。もう一度タップすると戻る。鍋に入るのは最大4つ。
- 「つくる」を押すと料理ができる。
  - 鍋の中身がレシピと**ぴったり同じ**(種類と数がすべて一致)なら、その料理ができる。順番は関係ない。
  - 合わなければ「ふしぎな料理」ができる。食べられるが、効果は弱い。
  - どちらの場合も、使った食材は減る。お米は減らない。
- 料理そのものには操作のゲームを入れない。ゲームの要素は食材集めのほうに置く。
- 【判断】料理は「ごはん」パネルの中にあるので、ごはんと同じく、卵のときと寝ているときはできない。
- 【判断】できたときは、鍋がグツグツする短い演出(1〜2秒)のあと「〇〇ができた!」と出す。初めて見つけたレシピなら「はじめて!」と分かるようにする。お世話の演出と同じ仕組み(`src/ui/effects/`)で作る。

### 5.2 レシピ帳 【オーナー】(提案に「OK」)
- 「ずかん」に「レシピ」のページを足す。
- 一度作れた料理は、材料と一緒にずっと残る。次からは組み合わせが分かる。
- まだ見つけていないレシピは「？？？」と、短いヒント(例:「魚を使う…」)だけを出す。
- 「みつけたレシピ 3 / 12」のように、見つけた数を出す。
- ふしぎな料理は、レシピ帳に載せない【判断】。

### 5.3 レシピの一覧(案)
【オーナー】の3つと、設計者の案9つ(オーナーが「OK」)。全部で12種類【オーナー】。料理の絵は、この一覧をもとに作る。

| ステーキ | 肉2・野菜1 【オーナー】 | ごはん |
| アクアパッツァ | 魚2・野菜2 【オーナー】 | ごはん |
| ケーキ | 果物3 【オーナー】 | おやつ |
| おにぎり | お米1・魚1 | ごはん |
| オムライス | お米1・たまご2 | ごはん |
| 海鮮どん | お米1・魚1・えび1 | ごはん |
| えびフライ | えび2・たまご1 | ごはん |
| ハンバーグ | 肉2・たまご1・野菜1 | ごはん |
| 野菜いため | 野菜3 | ごはん |
| きのこスープ | きのこ2・野菜1 | ごはん |
| 木の実クッキー | 木の実2・たまご1 | おやつ |

- 料理名は、一般的な料理名だけを使う。既存作品の名前やキャラクターは使わない。

## 6. ごはん(食べさせる)

- 【オーナー】(提案に「OK」)「ごはん」パネルの「たべる」タブには、持っているものだけを数つきで出す。
  - お米とあめは「∞」。
  - 手に入れた食材と作った料理には、持っている数を出す。
  - 0個のものは押せない(または出さない)。
- 食べさせると、食料庫から1つ減る。
- 料理は、そのままの食材より、おなかやごきげんが多く回復する【オーナー】(提案に「OK」)。具体的な数値はビルダーに任せる。
- おやつ(ケーキ・クッキー・タルト・あめ)は、今のおやつと同じく、食べすぎると病気になる仕組み(`sugar`)に数える【判断】。
- 食べさせたときの演出は、お世話の演出(ごはん)をそのまま使う。新しい食べ物の「かじった絵」は `scripts/art/bite.ts` で作る。

## 7. ゲームのルールへの影響

### 7.1 進化
- 今は、どの種類の食べ物を一番多く食べたか(`dominantFood`)で、若い姿への進化先が変わる。
  - 肉 → ヒノコ、魚 → シズク、野菜・お米 → メブキ、甘いもの → フワリ。
- 【オーナー】(提案に「OK」)料理は、主な材料の種類として1回数える(ステーキなら肉)。
  - レシピのデータに「数える種類」を1つ持たせる。
- 新しい食材の種類は 3章の表のとおり【判断】。
- 【判断】おでかけの上限(1日3回、1回最低1個)があっても、4つの若い姿のどれにも、ふつうに遊んで進化させられること。ビルダーは、1回の収穫量をこの条件で調整し、テストで確かめる(上限を変えるときは 4.1 のとおりオーナーに聞く)。
- 【判断】体重で決まる進化先(重い: ダンゴ・ポヨ)も、今と同じくらいの選ばれやすさを保つ。
  - いつでも出せる食事がお米だけになるので、お米ばかり食べて重い体型に偏りやすくなる。
  - 必要なら、お米の体重への効果などを調整する。
  - このことも、7.1 のテストで確かめる。

### 7.2 セーブ
- セーブに「食料庫」「レシピ帳」「おでかけの今日の回数」「畑の状態」を足す。
- **今のセーブは消さない。** 今のペットとずかんはそのまま残る。新しい項目がないセーブは、空の食料庫・空のレシピ帳・何も植えていない畑として読む【オーナー】(提案に「OK」:食料庫は空から始まる)。
- 本体と同じく、セーブは Zod で検証する。

### 7.3 ルールの置き場所
- 食材の収穫量、1日の上限、料理の判定、レシピ帳の更新は、すべて `src/core` の純粋な関数として書き、単体テストで確かめる。
- ポップアップは、ミニゲームの結果(点数)だけを背景に送る。手に入る食材は、背景側がルールと乱数で決める。
  - ポップアップから「肉を5個ください」のように、直接食材を増やすことはできない。
  - 送られてきた点数は、境界で検証する(範囲外なら断る)。
- 1日の上限は背景側(ルール)で守る。画面で押せなくするのは、見た目の補助にすぎない。

## 8. 画面と絵

### 8.1 画面 【オーナー】(提案に「OK」)
確認用ページのたたき台(`.superpowers/brainstorm/.../foraging-cooking-screens.html`)のとおり。
- ボタン: 今の7つに「おでかけ」を足して、4×2 に並べる。
- おでかけパネル: 4つの活動と、それぞれの「今日あと何回」(畑は育ち具合と水やりできるか)。
- ごはんパネル: 「たべる」「りょうりする」の2つのタブ。
- ずかん: 「ペット」「レシピ」の2つのページ。

### 8.2 新しい絵 【判断】
- 食材のアイコン5つ: えび・たまご・木の実・きのこ・果物(32×32)。
- 料理のアイコン12個: 新しい料理11個と、ふしぎな料理(32×32)。ケーキは今の絵を使う。
- 「おでかけ」ボタンのアイコン(16×16)。
- ミニゲームの絵:
  - 釣り: ウキ、水面。
  - 狩り: 草むら、飛び出すもの。
  - 採集: 茂み。
  - 畑: 種・芽・育った野菜/果物、じょうろ。
  - 必要なら、外の背景(川・森・野原・畑)。
- 料理の絵: 鍋、湯気。
- かじった絵は `scripts/art/bite.ts` で作る(新しい食べ物には、スクリプトを2回流すだけ)。
- すべて PixelLab で作り、マスターパレットに合わせて `scripts/art/check.ts --palette` を通す。
  - スタイルガイド(`docs/art/style-guide.md`)に従う。太い黒の輪郭線、レトロポップ。
  - PixelLab に頼むと、食べ物や小物にも顔が付くことがある(お世話の演出で9回中9回)。顔のない絵になるまで候補を選ぶか、コードで描く。
- PixelLab は、無料の月間枠の範囲だけで使う。`generations_remaining` が100未満なら、止めてオーナーに聞く(本体と同じルール)。

### 8.3 音 【判断】
今のチップチューンの仕組みで、短い音を足す。たとえば、釣れた・つかまえた・見つけた・収穫・グツグツ・できた。設定でオンのときだけ鳴る。

## 9. 確認の進め方 【判断】

マージする前に、オーナーに見てもらって承認をもらう。
- **絵の確認会:** 新しい食材・料理・ミニゲームの絵を、ポップアップと同じ4倍の大きさで見せる。
- **遊びの確認会:** 4つのおでかけと料理を、実際に動く様子(録画した GIF か、動く確認用ページ)で見せる。

## 10. 制約

- 本体の設計書(`docs/superpowers/specs/2026-11-03-chrometchi-rebuild-design.md`)の制約(9章)と開発ルールに従う。
  - TDD、カバレッジ80%以上。
  - 関数は50行未満、ファイルは800行未満。
  - 不変の書き方。
  - 既存作品の模倣をしない(名前・見た目・ゲームの見せ方)。
  - ポップアップは今の大きさ(360×462)のまま。
- 画面の文言は、日本語と英語の両方を用意する(`public/_locales/`)。
- ポップアップ全体の e2e テストに、少なくとも「おでかけで食材が手に入る」「料理してレシピ帳に載る」を足す。

## 11. ビルダーに任せること

- 4つのミニゲームの細かいルール(タイミングの幅、出てくる回数、めくれる回数など)と見た目。
- 1回の収穫量の決め方(点数から何個にするか、珍しい食材の出やすさ)。ただし最低1個と 7.1 の条件は守る。
- 畑の育つ時間、水やりの効果。
- 食材と料理の効果の数値(おなか・ごきげん・体重・元気)。
- レシピのヒントの文言。
- セーブへの項目の足し方(バージョンの上げ方を含む)。ただし今のセーブは消さない。
- 作業の分け方(たとえば「食料庫・ごはん・料理・レシピ帳」と「おでかけ4種」を別の計画にする)と順序。
